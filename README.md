# Эмулятор оболочки ОС — вариант №21

## 1. Общее описание

Практическая работа, этап 1: минимальная консольная оболочка (REPL).
Язык: Python 3.10 или новее. Внешние библиотеки для запуска не нужны.
Программа работает в Windows, Linux и macOS; интерфейс похож на UNIX.
Автоматические и терминальные проверки выполнены в Linux с Python 3.12.
Запуск в Windows предоставлен, но в этой среде не проверялся.

REPL означает Read — Evaluate — Print — Loop:
прочитать строку, разобрать и обработать её, вывести результат, повторить.

## 2. Функции и настройки

| Возможность | Поведение |
| --- | --- |
| Приглашение | `username@hostname:каталог$ `, значения получены из ОС |
| Домашний каталог | Заменяется на `~` только в приглашении |
| `ls [аргументы]` | Заглушка: печатает своё имя и список аргументов |
| `cd [аргументы]` | Заглушка: печатает своё имя и список аргументов |
| `exit` | Завершает эмулятор |
| `$NAME`, `${NAME}` | Подставляют значение из окружения процесса |
| `'текст'` | Сохраняет текст буквально, без раскрытия переменных |
| `"текст"` | Сохраняет пробелы внутри слова и раскрывает переменные |
| `\` вне кавычек | Экранирует следующий символ |
| Пустая строка | Показывает следующее приглашение |
| Неизвестная команда | Сообщение в stderr; работа продолжается |
| Синтаксическая ошибка | Сообщение в stderr; работа продолжается |
| Ctrl+C | Отменяет ввод; работа продолжается |
| EOF | Завершает работу без traceback |

В двойных кавычках обратная косая черта экранирует `$`, `"` и `\`.
Перед прочими символами она сохраняется буквально.
Аргументы печатаются как JSON-список: видны пустые строки и границы слов.
Например, `["a b", ""]` — два аргумента, второй пустой.

Файла конфигурации нет. Переменные берутся из `os.environ` при каждом
разборе. Для тестирования `parse_line` принимает отдельный словарь.
Приглашение использует `getpass.getuser()`, `socket.gethostname()`,
`os.getcwd()` и `os.path.expanduser("~")`.

На Windows переменная `HOME` может отсутствовать; используйте
`$USERPROFILE` либо заранее задайте `HOME`. Имена переменных в синтаксисе
парсера: латинская буква или `_`, затем буквы, цифры и `_`.

### Границы первого этапа

- `ls` не читает каталог; `cd` не меняет его и не проверяет существование.
- Внешние программы не запускаются. `eval` и системная оболочка не используются.
- Отсутствующая переменная даёт пустую строку; слово с ней сохраняется.
- После раскрытия переменных нет разделения на слова: `$X` со значением
  `a b` становится одним аргументом. Это упрощение относительно UNIX shell.
- Нет glob (`*`), раскрытия `~` в аргументах и комментариев через `#`.
  Эти символы остаются обычным текстом.
- Нет присваиваний переменных, специальных параметров `$?` и `$1`.
- Конвейеры, перенаправления, `;`, `&`, подстановка команд через `$()`
  и обратные кавычки вызывают ошибку, если не заключены в буквальные кавычки.
- Поддерживается одна строка ввода; перенос команд через `\` не реализован.
- У `exit` пока нет аргументов. `exit 1` сообщает об ошибке и продолжает REPL.

### Структура и назначение функций

```text
src/
    parser.py           Разбор строки
    shell.py            Приглашение, команды и цикл REPL
tests/
    test_parser.py      Проверки парсера
    test_shell.py       Проверки интерфейса и команд
tools/
    check_quality.py    Локальная формальная проверка
docs/
    defense.md          Подготовка к защите и публикации
    quality.md          Методика проверки оформления
    demo.txt            Запись запуска в псевдотерминале
run.sh                  Запуск в Linux/macOS
run.bat                 Запуск в Windows
```

| Функция или метод | Назначение |
| --- | --- |
| `parse_line` | Выбрать окружение и запустить отдельный экземпляр парсера |
| `Parser.__init__` | Сохранить строку, словарь окружения, позицию |
| `Parser.parse` | Собрать фрагменты в слова, разделяя их пробелами |
| `Parser.read_part` | Выбрать обработчик очередного символа |
| `Parser.read_single` | Прочитать буквальный текст в одинарных кавычках |
| `Parser.read_double` | Прочитать двойные кавычки с раскрытием переменных |
| `Parser.read_escape` | Прочитать экранированный символ вне кавычек |
| `Parser.read_double_escape` | Обработать экранирование внутри двойных кавычек |
| `Parser.read_variable` | Прочитать `$NAME` или передать разбор `${NAME}` |
| `Parser.read_braced_variable` | Проверить скобки, имя и получить значение |
| `display_directory` | Сократить домашний каталог в приглашении |
| `make_prompt` | Собрать приглашение из реальных данных ОС |
| `execute` | Вывести заглушку, ошибку или сигнал завершения |
| `run_repl` | Поддерживать диалог и обрабатывать исключения |

`ParseError` — отдельный тип синтаксической ошибки, наследник `ValueError`.
`execute` возвращает `False` только при корректном `exit`; иначе `True`.
`run_repl` принимает необязательные `reader`, `output`, `errors` для тестов;
в обычном запуске использует `input`, `sys.stdout`, `sys.stderr`.
Вспомогательные функции проверки и тестов документированы docstring.

## 3. Сборка, запуск и тесты

Сборка не требуется: Python выполняет исходный код непосредственно.
Все команды ниже выполняются из корня проекта, где находится README.md.

Linux/macOS:

```sh
sh run.sh
python3 -B -m unittest discover -s tests -v
python3 -B tools/check_quality.py
```

Windows (терминал PowerShell):

```powershell
.\run.bat
py -3 -B -m unittest discover -s tests -v
py -3 -B tools/check_quality.py
```

Если команда `py` отсутствует, но `python --version` показывает Python 3.10+:

```powershell
python -B -m src.shell
python -B -m unittest discover -s tests -v
python -B tools/check_quality.py
```

Проверка оформления требует Git, индексированных файлов и хотя бы одного
коммита. Она проверяет отслеживаемые файлы; перед ней добавьте изменения
в индекс и оформите коммит. Подробности: [docs/quality.md](docs/quality.md).

## 4. Примеры использования

Здесь имя, хост и `/home/student` условные; при запуске будут данные вашей ОС.

```text
student@laptop:~$ ls -la
ls: аргументы = ["-la"]
student@laptop:~$ cd "$HOME"
cd: аргументы = ["/home/student"]
student@laptop:~$ ls "${HOME}/My Documents" '$HOME' \$HOME
ls: аргументы = ["/home/student/My Documents", "$HOME", "$HOME"]
student@laptop:~$ ls ""
ls: аргументы = [""]
student@laptop:~$ unknown
unknown: команда не найдена
student@laptop:~$ ls "
Ошибка синтаксиса: Не закрыта двойная кавычка
student@laptop:~$ exit 1
exit: аргументы не поддерживаются
student@laptop:~$ exit
Выход из эмулятора.
```

Полная запись терминальной проверки: [docs/demo.txt](docs/demo.txt).
Порядок демонстрации и вопросы для защиты: [docs/defense.md](docs/defense.md).
