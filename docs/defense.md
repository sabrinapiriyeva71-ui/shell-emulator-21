# Подготовка к защите первого этапа

## Что нужно принести

По условиям задания защита проходит очно на семинаре, по этапам.
Можно сдавать только этап 1. Нужны публичная ссылка на репозиторий,
история коммитов, работающая программа, тесты и понимание реализации.
Точный порядок вопросов определяет преподаватель.

Скажите, что использовали ChatGPT (OpenAI) при подготовке реализации,
тестов и документации. Не называйте непроверенное обозначение модели.
Не утверждайте, что написали всё без помощи.

## Как устроена программа

1. `run.bat` или `run.sh` переходит в папку проекта и запускает модуль shell.
2. `run_repl` печатает заголовок и повторяет цикл `while True`.
3. `make_prompt` читает имя пользователя, имя компьютера и текущий каталог.
4. `input` показывает приглашение и читает одну строку.
5. `parse_line` создаёт парсер со строкой и окружением ОС.
6. Парсер идёт по символам и собирает список: имя команды, затем аргументы.
7. `execute` выбирает заглушку, выход либо сообщение о неизвестной команде.
8. При `exit` возвращается `False`, поэтому REPL заканчивается.
9. При ошибке синтаксиса выводится сообщение, затем запрашивается новая строка.

У парсера три поля: `line` — исходный текст, `position` — текущий индекс,
`environment` — словарь переменных. Позиция движется только вперёд.
`parts` накапливает фрагменты одного слова, `words` — готовые слова.
Флаг `started` отличает отсутствие слова от явно пустого аргумента `""`.

Пример: `ls "${HOME}/docs" '$HOME'`.
Первое слово — `ls`. Во втором двойные кавычки разрешают раскрытие HOME,
а `/docs` приклеивается к значению. Третье слово остаётся буквальным `$HOME`,
потому что одинарные кавычки запрещают раскрытие.

`VARIABLE_NAME` — регулярное выражение для допустимого имени переменной.
`match` ищет имя с текущей позиции, `fullmatch` проверяет имя целиком.
`environment.get(name, "")` возвращает значение или пустую строку.
Текст значения не разбирается повторно и не выполняется как программа.

## Демонстрация на 5–7 минут

Сначала запустите тесты и `tools/check_quality.py`, затем `run.bat`/`run.sh`.
Ниже команды вводятся уже в эмуляторе, а не в PowerShell или Bash.

```text
ls
ls -la /tmp
cd "my folder"
ls "$HOME" "${HOME}/docs"
ls '$HOME' \$HOME
ls "" $MIREA_DEMO_UNSET_21
unknown
ls "
ls ${HOME
ls | cd
exit 1
ls
exit
```

Перед демонстрацией убедитесь, что MIREA_DEMO_UNSET_21 не задана.
В Windows вместо HOME можно использовать USERPROFILE.
Либо до запуска эмулятора задайте в PowerShell `$env:HOME = $env:USERPROFILE`.
Если переменная HOME отсутствует, пустой результат её раскрытия корректен.

Дополнительно нажмите Enter на пустой строке и Ctrl+C: REPL продолжится.
Для EOF запустите программу ещё раз: Ctrl+D в Linux/macOS;
Ctrl+Z, затем Enter в Windows. Программа должна завершиться без traceback.
Обратите внимание: после `cd` приглашение не изменилось, это заглушка.

## Возможные вопросы

**Почему не `line.split()`?** Он неправильно разделит `"my folder"`.
Нужно учитывать кавычки, экранирование и переменные.

**Почему не раскрыть переменные перед разбором?** Тогда пробелы и кавычки
в значении могут ошибочно стать синтаксисом; также нужно учитывать `'...'`.

**Почему не используется готовый shlex?** В нём нужно отдельно сохранять
контекст кавычек для правильного раскрытия. Небольшой отдельный парсер
показывает этот контекст явно и позволяет объяснить обработку по символам.

**Меняет ли программа файлы?** Нет. `ls` и `cd` только печатают информацию.
Даже `cd /несуществующий` не проверяет путь на первом этапе.

**Чем stdout отличается от stderr?** Первый поток для результата,
второй для ошибок. В терминале обычно видны оба.

**Как тестируется интерактивная программа?** В тестах вместо клавиатуры
передаётся функция чтения, а вместо терминала — `io.StringIO`.
`unittest.mock.patch` подменяет данные ОС или имитирует EOF/Ctrl+C.
Отдельно есть реальный запуск программы через псевдотерминал в demo.txt.

**Что такое исключение?** Сигнал об ошибке. `ParseError` возникает при
ошибочном синтаксисе; цикл ловит его и продолжает работу.
EOF завершает цикл, KeyboardInterrupt отменяет текущий ввод.

**Какова сложность разбора?** При обычных словарных операциях — O(n + m),
где n — длина исходной строки, m — суммарный объём подставленных значений.
Память также O(n + m). Склеивание фрагментов выполняется через `join`.

**Что означает коммит?** Снимок отслеживаемых файлов с автором, временем
и сообщением. `feat(repl): ...` означает новую функцию в области repl.
`git status` показывает изменения, `git log` — историю снимков.

**Почему архив не нарушение Г1?** Архив — только упаковка для передачи.
Внутри Git отслеживаются исходники и документация, а не сам архив.

## Публикация на GitHub

1. Распакуйте архив целиком. Сохраните скрытый каталог `.git`:
   в нём уже находится коммит первого этапа. Повторный `git init` не нужен.
2. В терминале перейдите в `shell-emulator-21` и выполните `git log --oneline`.
3. Создайте на GitHub новый **Public** репозиторий `shell-emulator-21`.
   Не добавляйте автоматически README, .gitignore и лицензию.
4. В обычном терминале выполните команды ниже, заменив YOUR_LOGIN на свой логин.

```sh
git remote add origin https://github.com/YOUR_LOGIN/shell-emulator-21.git
git push -u origin main
```

Если сервис запрашивает вход, авторизуйтесь через стандартный механизм Git.
Пароли и токены не вставляйте в файлы проекта или сообщения коммитов.
Откройте публичную ссылку в приватном окне браузера и проверьте README,
папки src/tests и вкладку коммитов.

Подготовленный коммит создан от имени `ChatGPT` с техническим адресом
`chatgpt@example.invalid`; это явно отражает участие нейросети.
Для следующих собственных коммитов задайте своё настоящее имя и адрес Git:

```sh
git config user.name "Ваше имя"
git config user.email "Ваш адрес для Git"
```

Не публикуйте архив через кнопку загрузки файлов: так потеряется история.
Если скрытая папка .git потеряна при переносе, восстановите её повторной
распаковкой исходного архива.

После собственных изменений используйте подробный scoped-коммит:

```sh
git add src tests README.md docs tools run.sh run.bat .gitignore
git commit -m "fix(parser): correct variable handling" -m "Describe the corrected case and test results."
git push
```

Перед защитой полезно самостоятельно добавить один тест и объяснить,
какую конкретную ошибку он обнаружил бы. Не заучивайте ответы без запуска.
