# Проверка оформления

Локальная команда: `python3 -B tools/check_quality.py`.
На Windows: `py -3 -B tools/check_quality.py`.
Нужны Git, индексированные файлы и существующий коммит.

Это проверка по предоставленному перечню, а не программа преподавателя.
Исходный код и настройки его проверяющей системы не предоставлены.
Совпадение результата с неизвестным проверяющим скриптом не гарантируется.
Когда он станет доступен, нужно запустить именно его на этом репозитории.

| Правила | Способ проверки |
| --- | --- |
| С1–С5 | Наличие README.md, .gitignore, src, tests, скрипта запуска в индексе |
| С6 | Заголовки всех коммитов имеют вид `тип(область): описание` |
| Г1–Г5 | Запрет распространённых архивов, бинарников, кэшей и настроек IDE |
| Р1 | Каждый отслеживаемый файл содержит не более 1000 строк |
| Р2, Р6 | Python: не более 80 символов; остальные файлы: не более 120 |
| Ф1 | Каждая функция и метод Python занимает не более 40 строк |
| А1 | Не более 7 аргументов, включая self и вариативные аргументы |
| К1 | У модулей, классов, функций и методов есть docstring |
| Ц1 | Оценка сложности каждой функции не превышает 10 |
| М1 | В сравнениях AST нет числовых литералов, включая отрицательные |
| И1 | Базовая проверка формы имён; отдельное исключение для unittest.setUp |

Правила для JavaScript, Kotlin, Rust и прочих языков здесь неприменимы:
в проекте нет исходных файлов на этих языках.

## Как считается сложность

Начальное значение — 1. Учитываются if, циклы, тернарные выражения,
обработчики исключений, assert, логические операции, генераторы и else
циклов/try. Для используемого подмножества Python это консервативная оценка.
Разные инструменты могут по-разному учитывать assert, except и else.
Скрипт не предназначен для произвольного Python, например match/case.

## Ограничения локальной проверки

- Проверка имён — базовая, она не заменяет полный линтер PEP8.
- Документация проверяется на наличие; содержательность проверяется вручную.
- С6 проверяет scoped-заголовки; содержательность тела коммита — вручную.
- Бинарные файлы обнаруживаются по расширениям, UTF-8 и нулевым байтам.
- Скрипт берёт список из `git ls-files`, а содержимое — из рабочего дерева.
  Для проверки сдаваемой версии рабочее дерево должно быть чистым.
- Архив доставки находится вне репозитория. Его нельзя коммитить.
- Сам служебный каталог `.git` не является отслеживаемым содержимым.

Перед сдачей выполните тесты, проверку оформления, `git status --short`
и `git log --oneline`. Убедитесь, что `git status --short` ничего не выводит.
Публичная доступность репозитория проверяется отдельно в браузере без входа.

## Независимые инструменты и результат

Дополнительно выполнены pycodestyle 2.14.0 и Radon 6.0.1.
pycodestyle не обнаружил нарушений; максимальная сложность по Radon — 10
у `run_repl`. Все остальные функции, в том числе тесты и скрипт проверки,
имеют меньшую сложность. 16 unit-тестов прошли, включая параметризованные
подслучаи кавычек, переменных и ошибок. Запись PTY-сеансов — в demo.txt.

Для повторения независимой проверки (необязательно для запуска программы):

```sh
python -m pip install -r requirements-dev.txt
python -m pycodestyle --max-line-length=80 src tests tools
python -m radon cc src tests tools -s
```

Замените `python` на `python3` или `py -3`, если требуется в вашей ОС.
Radon печатает метрики; сам факт завершения команды не проверяет порог 10.
Локальный `check_quality.py` проверяет порог автоматически своей методикой.
